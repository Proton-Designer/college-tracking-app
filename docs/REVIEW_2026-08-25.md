   end-to-end: the first-ever user-JWT gateway call found a missing INSERT policy that
   three verification layers (service-role cron, direct-provider smoke, fixture tests)
   were each structurally unable to see. The gateway now fails *closed* on logging
   failure (unlogged spend must not return ok). Your §10.2 "false greens" section
   predicted exactly this shape.

   surfaced on the first live extraction. The wire schema now carries per-type shapes;
   types.ts and the tool schema are one contract written twice, with confirm.ts as the
   drift guard.
3. **SDK 54 + CLI 2.115.0 divergences from your §3.2 pins** are documented in HANDOFF
   (import_map requirement, gen-types metadata, db diff needs Docker). The React
   dedup for the monorepo lives in metro.config.js + a jest moduleNameMapper — remove
   both only by aligning web to mobile's React.
4. **Docs your handoff relies on that are now stale**: SCREEN_SPEC §0's mobile route
   list (D24), the enum list in DATA_MODEL for deliverable_type, and FOLLOWUPS rows
   L4 (resolved) / V1-adjacent items. I updated FOLLOWUPS where I touched things;
   SCREEN_SPEC and DATA_MODEL are *not* updated — flagged rather than silently edited,
